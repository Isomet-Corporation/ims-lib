Overview

The IMS SDK provides the official public interface for integrating with the IMS platform. It enables client applications, plugins, and external systems to interact with IMS components in a stable and supported manner.

The SDK is designed for:

  • High-performance native applications
  • Hardware integration
  • Automation systems
  • External tooling and data processing pipelines

This documentation is generated directly from the distributed public headers, ensuring alignment between the SDK reference and the shipped binaries.

Version Information

SDK Version: 2.0.7

The shared library follows semantic versioning:

  • Linux: libims.so.<major>.<minor>.<patch>
  • Windows: imsLibrary.dll

Backward compatibility is guaranteed within the same major version.

Debug builds are available with a 'd' suffix

Installation

The SDK distribution contains:

  • include/ — Public header files
  • lib/ — Import libraries and shared libraries

Linux

Link against:

-lims (Release)
-limsd (Debug)

Ensure the shared library is available in:

  • LD_LIBRARY_PATH, or
  • /usr/lib, or
  • application rpath

Example:

g++ main.cpp -I/path/to/sdk/include -L/path/to/sdk/lib -lims

Windows

Link against:

  • imsLibrary.lib (Release)
  • imsLibraryd.lib (Debug)

Ensure imsLibrary.dll (or imsLibraryd.dll) is available on the system PATH or alongside your executable.

Threading Model

Unless explicitly stated:

  • Public API functions are thread-safe.
  • Individual object instances are not implicitly synchronized.
  • The caller is responsible for concurrency control where required.

Memory Ownership

The API follows strict ownership conventions:

  • Functions that allocate memory document ownership explicitly.
  • Objects created via factory functions must be destroyed using matching API calls.
  • Caller-provided buffers must meet documented size requirements.

Failure to adhere to documented ownership rules results in undefined behavior.
